# Kody Privacy — short draft

**Unpublished draft, 18 October 2026. This is proposed text for review, not a notice currently published to users.**

- **What we keep:** Your username, email, password hash, verification and security records, saved learning progress, submitted code and reactions. Profile names and pictures are optional. Role applications include the credentials you submit. Enabled financial features keep transaction records. Never send passwords or API keys to support.
- **Why:** To run your account, protect sign-in, deliver learning activities, review content and applications, record progress and resolve support or financial issues. Public attribution uses your username. Profile names, email and credential documents are not public profile fields.
- **Who can see it:** Authorized staff can access the records needed for their duties. Private uploads use authorized access. Publicly published learning content and eligible public leaderboard results can be seen by other users.
- **Providers:** Google sign-in, SendGrid email, Judge0 execution and Xendit payments have supporting code but live setup is currently deferred. Enabling them requires an updated notice describing the actual provider, information sent and purpose. Embedded YouTube media contacts its provider and follows that provider's privacy practices.
- **Your device:** Kody uses session cookies and local settings for themes, tutorials, companion position and guest practice. Guest practice is local to the browser. These settings are not proof of saved learning progress.
- **Your choices:** You can edit your profile, remove a picture, manage linked sign-in when available and request account deletion. Contact kody.support@gmail.com for access, correction or other privacy requests. Identity verification may be needed. Some security, financial and shared-content history may need to be retained; deletion is not an unconditional immediate purge.
- **Protection and retention:** Access controls, password hashing and private storage help protect records. No system can guarantee perfect security. We must publish the actual retention periods and handling of backups before public launch.

Before publication, identify the controller/operator and postal contact, document lawful purposes and retention periods, confirm hosting/transfers and enabled providers, and review age/minor handling and rights procedures. This draft does not establish compliance or change existing retention jobs.
